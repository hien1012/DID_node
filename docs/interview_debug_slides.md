# ESP32-S3 採集節點：Debug 紀錄（面試簡報用）

> 給簡報工具的說明：共 7 頁，語氣平實、不誇大。數據為實測值，標「預估」「待驗證」者除外。
> 第 3、5 頁適合做成長條圖；第 4、6 頁適合做成流程或表格。

## 1. 專案與系統
- ESP32-S3 野外節點：每 10 分鐘同時錄影（640×480 灰階 5 fps）與錄音（16 kHz），存 SD 後經 Wi-Fi 上傳
- 資料流：相機／I2S DMA → 內部 RAM → SD → HTTP 上傳 → 伺服器 ACK 後刪檔
- 限制：SD、I2S 的 DMA 只能用內部 RAM（約 300 KB）
- 我負責：韌體架構、量測工具、PC 端接收與分析程式

## 2. 問題一：SD 卡寫入逾時
- 現象：錄影一開始 SD 就無回應（0x107）
- 處理：相機初始化後才掛 SD、縮短接線、SD 電源改接另一支 3.3V、換卡
- 時脈：20 MHz 每幀 184 ms（週期 200 ms，餘量不足）→ 40 MHz 每幀 96 ms

## 3. 問題二：上傳只有 0.3 MB/s — 切分範圍
- 無線鏈路（iperf）7.5 MB/s、PC 伺服器 132 MB/s → 都不是瓶頸
- 韌體內直接送 RAM 資料：相機初始化前 4.9 MB/s，之後 0.07 MB/s
- 兩個原因
  - 內部 RAM 不足（剩 33.8 KB）→ 網路堆疊改用 PSRAM（剩 80.7 KB）
  - 相機匯流排干擾 Wi-Fi：時脈開 0.41 / 關 3.85 / 再開 0.48 MB/s → 非錄影期間停止相機與麥克風時脈

## 4. 問題二：讀 SD 與並行化
- 讀 SD 佔上傳時間 83%：fread 逐 sector 讀 1.07 MB/s → read() 讀 16 KB 到對齊緩衝 4.0 MB/s
- 讀與送改為兩個 task 並行（雙緩衝；讀 Core 1、送 Core 0）
- 錄影與上傳共用同一塊 32 KB 緩衝，內部 RAM 多出約 24 KB
- 92 MB 上傳：104 s → 37 s（AP 20 MHz 頻寬；40 MHz 下預估約 25 s，未實測）

## 5. 問題三：錄影影像損壞
- 現象：條紋、整片灰、錯位；錄影統計與驅動皆無錯誤
- 工具：PC 端 RAW 逐幀統計、相機串流模式（不經 SD）
- 逐一排除：解碼、感測器、寫 SD、資料線、接地、麥克風線材
- 關鍵 A/B：I2S 不啟動 → 50/50 正常；I2S 運作但 BCLK 由 GPIO14 移到 GPIO47 → 50/50 正常
- 根因：BCLK（約 1 MHz）與相機 PCLK（GPIO13）相鄰，杜邦線並排耦合
- 待驗證：示波器量 BCLK／PCLK 波形

## 6. 檢討與方法
- 早期誤判（寫 SD、資料線、接地）：對照組同時停了 I2S，有兩個變因
- 之後每次 A/B 只改一個條件
- 先量測切分範圍，再處理細節；每次測試記錄條件與數據（共 34 筆）
- 同樣做法已套用到舊版 ESP32 韌體（停時脈、吞吐量 A/B、串流），待上板驗證

## 7. 未解決
- 串流模式仍有 1.3% 可疑幀，原因未確定
- 錄影期間內部 RAM 最低約 2.7 KB，設定已修正待驗證
- 40 MHz SD 長時間穩定性需連續 10 輪以上測試
